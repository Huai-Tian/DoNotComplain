# DoNotComplain

简体中文 | [English](README.md) | [AI 协作文档](README_AGENT.md)

## 它是做什么的

**DoNotComplain** 是一个 LSPosed 模块：当你关闭了某个应用的通知后，它会阻止该应用察觉这件事——于是那些"开启通知，不错过重要消息"的弹窗、横幅、红点提醒，从此消失。

它**不会**重新打开你的通知。通知依然是关闭的、依然不会送达——只是应用不再为此骚扰你。

## 效果

- ✅ 应用内的"开启通知"引导弹窗、横幅消失
- ✅ 系统设置里，该应用的通知开关依然显示为**关**（真实状态不变）
- ✅ 通知确实不会送达（你关的就是关的）
- ✅ 覆盖设备上**所有**应用，无需逐个配置
- ✅ 在 LSPosed 里禁用模块并重启，一切恢复原状

## 已验证

真机实测通过：

- OPPO PGX110 / ColorOS 15（Android 15）
- OPPO PLR110 / ColorOS 16（Android 16）

多款主流应用的"开启通知"引导全部消失；系统通知开关的真实状态与投递行为不受影响。

理论上支持 Android 8.1 及以上；除 ColorOS 外的 ROM 未经充分实测，遇到问题时请携带 LSPosed 日志反馈。

## 使用方法

前提：已 root 的设备，装有 [LSPosed](https://github.com/LSPosed/LSPosed)（或兼容 libxposed API 102 的框架）。

1. 安装 APK
2. 打开 **LSPosed → 模块 → DoNotComplain → 启用**
   （作用域已内置固定，无需手动勾选任何应用；LSPosed 界面里的勾选操作会被自动还原，属正常现象）
3. 重启手机
4. 打开一个你关过通知的应用试试——它不再提示了

验证生效：LSPosed 日志中出现 `Installed N hooks in system_server`（N > 0）。

## 它做不到什么（诚实边界）

- **应用自己设置页里的推送开关**：部分应用有独立的"应用内消息开关"，横幅提醒的是这个开关而非系统权限——去应用自己的设置里打开即可，这不是本模块的对抗目标
- **系统弹出的权限申请对话框**：应用主动申请权限时 Android 系统显示的标准弹窗，属于系统 UI，不受影响
- **联网后服务端下发的运营弹窗**：与应用本地权限状态无关的推广内容

## 风险须知

- 模块运行于系统核心进程（system_server）。**理论上**，模块缺陷或与某些非常规 ROM 的冲突可能导致无法开机——此时可通过 recovery 卸载模块恢复。已验证机型上无此问题，但请知悉此风险并做好备份
